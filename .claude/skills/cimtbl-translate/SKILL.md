# Translating a model to .cimtbl

The format itself (Object/Table rows, `(unit)` headers, `Import`, `node`/`bus`/`phases`
shorthand) is defined by the `cimtables` package (`PNNL-CIM-Tools/CIM-Tables`, its
`CLAUDE.md`). This skill covers the conventions this repo's models follow on top of it.

**Worked example - read it first:** `distribution/IEEE/IEEE13_CDPSM/` (`README.md` has the
OpenDSS -> CIM mapping per element type, file split, and the realism audit).

## Identity: every row is keyed by mRID

- `Profile = cim18v17` at the top of every file.
- The file that defines a model (the master; for the tiered models, the `common.cimtbl`
  every tier imports) also declares its model scope, right under `Profile`:
  ```
  Authority = https://github.com/PNNL-CIM-Tools/CIMTBL-Models
  Model = IEEE13_CDPSM
  ```
  `Model` is unique per model in this repo (the master's file name, e.g.
  `padmount_example`). Files imported by more than one model (element-family parts,
  `templates/`) declare neither: Import raises if two files in a chain disagree.
- The first column of an `IdentifiedObject` row is **`mRID`** (required). It is a
  freeform string that must be **unique within the whole model**, across all classes
  (CIM 18). The loader rejects a reused mRID.
- Every reference cell (`BaseVoltage=`, `PowerTransformer=`, `EquipmentContainer=`, ...)
  holds the target's **mRID**. Declare targets before the rows that reference them.
- `name` is optional, non-unique data. Use it for the source tool's name (the OpenDSS
  element name) whenever the mRID adds a prefix.
- Classes that are **not** `IdentifiedObject`s (CIM 18 Identity only, e.g.
  `PhaseImpedanceData`) have no mRID or name. Give them an `identifier` column instead.
  It is optional, but write one so UUIDs stay the same between exports:
  `<parent mRID>_<row><column>` for matrix entries, e.g. `lc_mtx601_21`.
- The UUID is seeded from `Authority` + `Model` + class + mRID, so bus `671` in two
  models gets two UUIDs. Renaming (`name`) never changes identity; changing an mRID or
  the `Model` does.

## mRID prefixes

**This table is owned by the model maintainers. Edit it here; don't invent new prefixes
in a translation.** The rule is `prefix + source name`, lowercased, e.g. `ld_671`.

| Prefix | Classes |
|---|---|
| *(none)* | ConnectivityNode, TopologicalNode: the bare bus name (`650`, `rg60`, `sourcebus`) |
| `rgn_` / `srgn_` | GeographicalRegion / SubGeographicalRegion |
| `sub_` | Substation |
| `fdr_` | Feeder |
| `area_` | ConnectedArea |
| `bv_` | BaseVoltage, by voltage: `bv_4p16kv`, `bv_480v`, `bv_240v` |
| `zip_` | LoadResponseCharacteristic: `zip_constant_pq`, `zip_constant_z`, `zip_constant_i` |
| `src_` | EnergySource |
| `ln_` | ACLineSegment |
| `sw_` | every Switch subclass (Breaker, Recloser, Fuse, Sectionaliser, LoadBreakSwitch, Disconnector), so changing the device class keeps the mRID |
| `xf_` | PowerTransformer |
| `vr_` | VoltageRegulator (step-voltage regulator) |
| `ld_` | EnergyConsumer |
| `cap_` | LinearShuntCompensator |
| `pv_` / `storage_` | PowerElectronicsConnection for a PV system / a storage unit |
| `lc_` | PerLengthPhaseImpedance (OpenDSS LineCode) |
| `xc_` | TransformerTankConfiguration (OpenDSS XfmrCode) |
| `xb_` | TransformerBankConfiguration (a bank of tank configurations) |
| `wire_` | OverheadWireInfo (OpenDSS WireData): `wire_acsr_556_5` |
| `cable_` | ConcentricNeutralCableInfo, TapeShieldCableInfo (OpenDSS CNData, TSData): `cable_cn_250` |
| `spc_` | XYSpacing (OpenDSS LineSpacing) |
| `wc_` | WireConfiguration (OpenDSS LineGeometry) |

**Child rows** extend their parent's mRID with a suffix, so they need no prefix of their
own:

| Child | mRID |
|---|---|
| PowerTransformerEnd | `<xf>_<endNumber>` |
| TransformerMeshImpedance | `<xf>_mesh_<from><to>` |
| TransformerTank | `<xf>_tank` |
| TransformerPhaseEnd (instance) | `<xf>_<endNumber>_<phase>` (`xf_xfm1_2_n`) |
| TransformerLug, TransformerWinding, configuration mesh | `<xc>_lug_<designation>`, `<xc>_wdg_<from><to>`, `<xc>_mesh_<leg>` |
| AutoTransformerEnd, regulator lug, winding, mesh | `<vr>_<endNumber>`, `<vr>_lug_s` / `_l` / `_sl`, `<vr>_wdg`, `<vr>_mesh_12` |
| RatioTapChanger, TapChangerControl | `<xf>_tap`, `<xf>_ctrl` (regulators: `<vr>_tap`, `<vr>_ctrl`) |
| OperationalLimitSet, CurrentLimit | `<ln>_limits`, `<ln>_normal` |
| PhotoVoltaicUnit / BatteryUnit | `<pec>_unit` |
| XYConductorPosition | `<spc>_<n>` (n = conductor number) |
| WireSequenceConfiguration | `<wc>_<n>` (n = conductor number) |
| RegulatingControl (capacitor control) | `<cap>_ctrl` |

**Generated by the loader, never written:** Terminals `<equipment mRID>_T<n>` (a
TransformerEnd's terminal is `<xf>_T<endNumber>`, an AutoTransformerEnd's `<vr>_T<endNumber>`),
and phase children `<mRID>_<phase>` (delta branches `<mRID>_<AB>`). A reference to a generated
Terminal uses that mRID, e.g. `TapChangerControl.Terminal = vr_reg1_T2`.

## Translation rules (summary; details in the IEEE 13 README)

- **Files:** one master that holds the containers, BaseVoltages, load models and source,
  then `Import`s one file per element family in dependency order: linecodes, xfmrcodes,
  transformers, regulators, switches, lines, loads, capacitors, der.
- **Units:** transcribe values as written in the source, with their unit in the header
  (`length (ft)`, `p (kW)`, `r (ohm/mile)`, `r (percent)`). Never pre-convert.
- **Connectivity:** `node`/`node1`/`node2` = the bus name without node suffix.
  `phases` = the node suffix in written order (`.3.2` -> `CB`; split-phase `.1.2` ->
  `s1s2`). `N` only for a real neutral conductor. No suffix = `ABC`.
- **Sign:** CIM load convention, so generation and discharge are negative `p`.
- **BaseVoltage:** `nominalVoltage (kV)`, phase-to-phase, as written in `Set Voltagebases`.
- **No Kron reduction.** Write line matrices as given (4x4 with the neutral, `kron=yes`
  ignored) and give the line its neutral: `phases=ABCN`, `s1s2N`. Reduction is the
  converter's job.
- **Line geometry:** LineSpacing -> `XYSpacing` + `XYConductorPosition` (not the deprecated
  `WirePosition`); LineGeometry -> `WireConfiguration` (`WireSpacing=`), its `wires=[...]` ->
  one `WireSequenceConfiguration` per conductor (`sequenceNumber`, `WireInfo`).
- **CapControl** -> `RegulatingControl` on the capacitor: voltage mode, `targetValue` =
  (on + off) / 2, `targetDeadband` = off - on (on the PT secondary values x ptratio),
  `Terminal` = the monitored element's terminal; the delay goes on the capacitor's
  `aVRDelay`. Values with no CIM attribute (time-of-day settings) go in the README.
- **Regulators** (an OpenDSS Transformer under a RegControl, a CYME Regulator) follow
  `distribution/regulator_example.cimtbl`: one `VoltageRegulator` per single-phase unit
  (taps differ per phase; a bank is not represented), two `AutoTransformerEnd`s keeping the
  OpenDSS two-winding shape (end 1 = S, source; end 2 = L, load; `node`, `phase` = the unit's phase
  to neutral, `AN` / `BN` / `CN`; `baseU` = the coil kV, `ratedS` = the through rating, OpenDSS
  `kvas`), lugs S / L / SL, one `TransformerWinding` S -> SL with `AutoTransformerLug` = L
  and `ratedS` = the buck/boost rating (range x through rating; a CYME `RatedKVA` already is
  it), then `Update VoltageRegulator: AutoTransformerWinding=`. Series impedance (OpenDSS
  `xhl`, `%r` per winding summed) is one `TransformerMeshImpedance` between the two ends, in
  percent on end 1's `baseU^2 / ratedS`. `RatioTapChanger` on end 2 (OpenDSS `winding=2`),
  `TapChangerControl.Terminal` = `<vr>_T2`. Leave `construction` (type A/B) unset unless the
  source says.
- **Regulator taps:** set `step` to the solved tap where the source gives one (including a
  commented "solution" script); otherwise `step = normalStep` and say so in the README.
- **XfmrCodes / transformer catalogs** become tank-only templates (the
  `cimtbl-transformer-template` skill): one `TransformerTankConfiguration` per code, 1:1 with
  the source, with lugs numbered by conductor in terminal order, one winding per coil, one
  mesh per leg. Each instance is a `PowerTransformer` + `TransformerTank`
  (`TankConfiguration=`) + `PowerTransformerEnd`s (`node`, `phases`, connection, grounding,
  no ratings) + `TransformerPhaseEnd`s with the lug numbers and the real phases. A
  transformer with no code stays a direct `PowerTransformer` with per-end ratings, `r` and a
  mesh. Worked examples: `IEEE13_assets` (Dyn1, YNyn0), `IEEE13_OCHRE` (center-tap, YNyn0).
- **Center-tap transformers** follow `distribution/templates/padmount_1ph_250kva.cimtbl`
  (instance: `distribution/padmount_example.cimtbl`): the template is the tank
  (`TransformerTankConfiguration` + `TransformerLug`s numbered by the conductor they land
  on + `TransformerWinding`s + meshes); the instance's `TransformerPhaseEnd`s carry the
  same numbers and the real phases. Each half winding has `ratedS` = its own rating (half
  the tank kVA) and `baseS` = the tank kVA (OpenDSS `kvas`, the base for both halves);
  `ratedU` = the phase-to-phase nameplate designation, `baseU` = the coil voltage
  (OpenDSS `kvs`).
- **New tank templates** from a winding diagram or nameplate (wye-wye, delta-wye, ...):
  the `cimtbl-transformer-template` skill (template = the tank; phases = the instance).
- **Concepts CIM 18 lacks** (e.g. a distributed load): approximate them (a distributed
  load is lumped at an added mid-line node, like OpenDSS IEEE 13's 670) and log a `TODO
  (CIM18 gap)` entry in the model README and in `distribution/CIM18_GAPS.md`.
- **Percent impedances** go on the winding base (`r (percent)` on the end's own
  ratedU²/ratedS; mesh `x (percent)` on the From end). Don't convert to ohms by hand.
- **Audit the values; don't just copy them.** Note every deviation from the source deck
  in the model's README (see the IEEE 13 realism audit).

## Check the translation loads

From the CIM-Tables checkout's environment (adjust the path to yours):

```bash
uv run --project /home/ande188/CIM-Tables python -I .claude/skills/cimtbl-translate/check_cimtbl.py path/to/master.cimtbl
```

It loads the master (imports included) with `cimtables.load_model`, fails with the file
and line of the first bad row, and prints the profile, model scope, container and object
counts. Errors you'll see:

- `mRID 'x' ... is already used by <Class>`: two rows share an mRID; apply the prefixes.
- `<attr> 'x' (<Class>) not found in graph`: the reference is misspelled or declared
  later; reorder.
- `mRID 'x' is a <A>, not a <B>`: the reference points at an object of the wrong class.
- `<Class> row has no mRID` / `is not an IdentifiedObject`: wrong key column for the
  class (see Identity above).
